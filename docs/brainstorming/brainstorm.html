✦ Technique 1 of 3 — Quantum Tunneling

Tunneling Through
Conventional Pipelines

Ideas that bypass the obvious path — each a wormhole to a better architecture, discovered by asking "what if we ignored the constraints first?"

⚖️

Signal Engine

Typed Diff with Confidence Scores

A structured comparator between the existing OBDB record and the candidate update — every field change carries a confidence float, not just a yes/no.

🔗

Provenance Chain

Evidence Citations per Field

Every proposed change cites its source URL and the exact extracted text snippet. Blame is always traceable to an atom of evidence.

🏠

Ground Truth Signal

Official Website as Closure Oracle

If the brewery's own homepage 404s or contains "permanently closed" language, that's high-confidence closure evidence — no LLM required in v0.1.

🏛️

Authoritative Source

State & Federal Licensing APIs

CA ABC, TTB, and equivalent state liquor control boards hold ground-truth licensing data. Structured, deterministic, legally authoritative.

💾

Cache Strategy

Bulk-Pull, Reuse per Lookup

Pull and cache a full state/city dataset once per TTL window. Every subsequent per-brewery lookup becomes a local read — API costs collapse.

🐝

Scale Design

One Brewery, Designed to Swarm

Each agent run handles exactly one brewery. Self-contained, auditable, composable. Horizontal scale is an emergent property, not a feature to build.

✦ Technique 2 of 3 — Job to Be Done

The Job the User
Is Hiring This Agent For

Strip away the technology. What frustration is this tool actually hired to resolve? One sentence — the rest is implementation detail.

Core JTBD Statement

"I see something wrong on OBDB → I want it fixed without 10 minutes of manual tab-hopping"

North-Star Vision

A "Research" button on every brewery's OBDB page
→ agent fires → GitHub PR with evidence lands

The v0.1 CSV diff with copy button is the interface fidelity prototype of that button. Every local UX decision should feel like that future press.

Fear to Neutralize

The Low-Quality PR Flood

The maintainer's biggest risk: a swarm of poorly-evidenced PRs that pollute the dataset and overwhelm the review queue. The confidence gate and evidence-only display below threshold are the direct antidote.

Surprise Upside

Quality Compounds, Community Follows

Dataset quality improves dramatically → community engagement snowballs → more contributors → richer data → better agent → repeat. A quality flywheel, not a one-shot fix.

Future Scope Signal

Web Search Serves Two Jobs

When web search lands in v0.2, it serves dual purpose: verify existing fields AND discover missing fields. Both jobs in one layer — keep both in scope.

Schema Reality Check

Closed = brewery_type:'closed'

No dedicated status field today. SCD type 2 tags are coming. The diff engine must be designed to handle both conventions without a rewrite at schema migration time.

▶ v0.1 — Deterministic Pipeline (NOW)

OBDB + State API + Confidence Ladder + Diff Output

  • OBDB record lookup by name + location
  • State API adapters: California (CA ABC), Colorado, Texas
  • Bulk cache + TTL — one API pull per state window
  • Website HTTP status check + closure keyword scan (no LLM)
  • Confidence ladder → typed diff with evidence chain per field
  • Output gate: above threshold = CSV diff + copy button; below = evidence display only
  • Schema designed for SCD type 2 tag migration readiness
  • Adapter interface (Should) + eval harness (Should)
Load-bearing constraint: without state API, the only deterministic source is the brewery website — which requires LLM extraction. State API is what makes v0.1 truly deterministic.

// key_insight_connections

01

Swarm design + evidence chain are the same idea. Self-contained, auditable, composable units. The cache is what makes both cheap — a single bulk pull amortizes the cost of every individual brewery query in that state window.

02

The eval harness doubles as training data. Ground-truth test cases built for v0.1 deterministic validation become the labeled dataset for v0.2 ML/LLM extraction. Build it right the first time and you build two things at once.

03

North-star vision implies interface fidelity today. The v0.1 local CSV diff + copy button should feel exactly like "that button" on the OBDB site. The interface prototype is not a throwaway — it is the user experience foundation.

04

State API is load-bearing for v0.1 determinism. Without it, the only available source is the brewery website — which requires LLM extraction. That's v0.2 territory. State API is what makes the v0.1 promise of a fully deterministic pipeline real.

05

The confidence gate neutralizes the maintainer's core fear. Below-threshold results show evidence but withhold the copy button. The human is always in the loop — not as a fallback, but as the designed happy path.
